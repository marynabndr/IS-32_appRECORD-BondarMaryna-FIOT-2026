## Тема,  Мета

**Тема:** Документування API за допомогою Swagger. Деплой Node.js-додатку. Підсумковий проєкт: REST API з MySQL.

**Мета:**
-	розуміти принципи документування REST API;
-	навчитися використовувати Swagger/OpenAPI для автоматичної документації;
-	навчитися інтегрувати Swagger у Node.js + Express застосунок;
-	створювати опис endpoint-ів, параметрів та моделей даних;
-	виконувати деплой Node.js-додатку на хмарний сервіс;
-	тестувати API через Swagger UI.

### Встановлення бібліотек

- ```swagger-ui-express``` створює сторінку в браузері з інтерфейсом

- ```swagger-jsdoc``` дозволяє писати опис API прямо в коментарях до коду.

```
npm install swagger-ui-express swagger-jsdoc
```

### Інтеграція Swagger UI у проєкт

**swaggerOptions** - описує правила, за якими Swagger буде будувати сторінку з інструкціями для API.

У константі swaggerOptions додали блок components. Це каже Swagger: «Ми використовуємо HTTP-авторизацію за схемою Bearer (токен), формат токена — JWT».

```
http://localhost:3000/api-docs
```

```
const swaggerOptions = {
  definition: {
    openapi: '3.0.0',
    info: {
      title: 'Global Talk API - Final Project',
      version: '1.0.0',
      description: 'Документація API для роботи з курсами, вчителями та профілем',
    },
    servers: [{ url: 'http://localhost:3000' }],
    // Додаємо можливість вводити JWT токен у Swagger
    components: {
      securitySchemes: {
        bearerAuth: {
          type: 'http',
          scheme: 'bearer',
          bearerFormat: 'JWT',
        },
      },
    },
  },
  apis: ['./server.js'], 
};
```

### Документація всіх endpoint-ів

```
app.post('/api/register', ...)
```

```
/**
 * @openapi
 * /api/register:
 *   post:
 *     tags: [Auth]
 *     summary: Реєстрація нового користувача
 *     requestBody:
 *       required: true
 *       content:
 *         application/json:
 *           schema:
 *             type: object
 *             properties:
 *               name: { type: string }
 *               email: { type: string }
 *               password: { type: string }
 *     responses:
 *       201:
 *         description: Користувач успішно зареєстрований
 *       400:
 *         description: Помилка валідації
 */
```

```
app.post('/api/login', ...)
```

```
/**
 * @openapi
 * /api/login:
 *   post:
 *     tags: [Auth]
 *     summary: Вхід у систему (Авторизація)
 *     requestBody:
 *       required: true
 *       content:
 *         application/json:
 *           schema:
 *             type: object
 *             properties:
 *               email: { type: string }
 *               password: { type: string }
 *     responses:
 *       200:
 *         description: Повертає JWT токени
 *       401:
 *         description: Невірні дані входу
 */
```

```
app.get('/api/profile', ...)
```

```
/**
 * @openapi
 * /api/profile:
 *   get:
 *     tags: [Profile]
 *     summary: Отримати дані профілю поточного користувача
 *     security:
 *       - bearerAuth: []
 *     responses:
 *       200:
 *         description: Дані профілю успішно отримано
 */ 
```

У верхній частині та біля окремих маршрутів видно іконку замка. Це свідчить про реалізацію схеми Bearer Authentication (JWT). Це дозволяє користувачу натиснути на кнопку «Authorize», вставити свій токен доступу один раз, і Swagger автоматично додаватиме його до заголовків усіх наступних захищених запитів.

Маршрути логічно розділені на секції (теги) для зручності розробника:
- **Auth (POST):** Маршрути для реєстрації, входу та виходу з системи. /api/logout має іконку замка, оскільки вийти може лише авторизований користувач.
- **Profile (GET, PUT, DELETE):** Повний набір CRUD-операцій для керування профілем користувача. Всі три методи захищені (потребують JWT).
- **Public Data (GET):** Публічні запити для отримання списків курсів (з підтримкою кешування), викладачів та відгуків. Ці запити не мають замків, отже доступні всім.
- **User Actions (POST):** Містить метод /api/apply для подачі заявки на курс. Маршрут захищений, оскільки заявка має бути прив'язана до конкретного користувача.
- **Files (POST):** Два методи для завантаження файлів. /upload-secure містить опис валідації типів, що було реалізовано у попередніх завданнях.
- **General (GET):** Службові маршрути, включаючи перевірку стану сервера (/status) та головну сторінку (/).

### Висновки

У ході виконання лабораторної роботи №6 було опановано методи професійного документування та розгортання серверних застосунків.

Основні результати роботи:
1. **Документування:** За допомогою бібліотек swagger-ui-express та swagger-jsdoc було створено інтерактивну документацію згідно зі стандартом OpenAPI 3.0. Це дозволило візуалізувати структуру API, описати моделі даних та згрупувати методи за функціональним призначенням.
2. **Тестування:** Реалізовано підтримку JWT-авторизації (Bearer Auth) безпосередньо у вебінтерфейсі Swagger, що дало змогу успішно протестувати як публічні, так і захищені маршрути профілю користувача без використання сторонніх інструментів (наприклад, Postman).
3. **Деплой:** Проєкт було успішно підготовлено до роботи у хмарному середовищі (налаштовано динамічні порти та start-скрипти) та розгорнуто на платформі Render. Отримано публічний URL, що підтверджує працездатність коду в реальних умовах.
4. **Підсумок:** Створено цілісний «підсумковий проєкт», який поєднує в собі логіку REST API, роботу з базою даних MySQL, систему безпеки та професійне технічне супроводження у вигляді автоматизованої документації.

## Відповіді на контрольні запитання

1. **Що таке REST API?** Це архітектурний стиль взаємодії компонентів веб-додатка через HTTP за допомогою стандартних методів (GET, POST, PUT, DELETE).

2. **Для чого використовується Swagger?** Для автоматичного створення інтерактивної документації API, яку можуть читати і тестувати інші розробники.

3. **Що таке OpenAPI?** Це загальноприйнятий стандарт (специфікація) для опису RESTful API.

4. **Які HTTP-методи використовуються у REST?** GET (читання), POST (створення), PUT/PATCH (оновлення), DELETE (видалення).

5. **Для чого потрібен swagger-jsdoc?** Для того, щоб писати документацію прямо в коді Node.js у вигляді JSDoc-коментарів.

6. **Що таке endpoint?** Це конкретний шлях (URL) в API, за яким доступний певний ресурс або дія.

7. **Які переваги Swagger UI?** Наочність, можливість тестувати запити без Postman, завжди актуальна документація.

8. **Для чого використовується Express.js?** Це швидкий і мінімалістичний фреймворк для створення веб-серверів на Node.js.

9. **Що таке деплой?** Процес перенесення коду з локального комп'ютера на сервер (хостинг), де він буде доступний через інтернет.

10. **Для чого потрібен GitHub під час деплою?** Він слугує сховищем коду і джерелом, з якого сервіси деплою (як Render) автоматично завантажують останню версію додатка.
